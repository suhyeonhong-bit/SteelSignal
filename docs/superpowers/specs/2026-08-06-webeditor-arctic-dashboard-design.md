# WebEditor용 북극 에너지 대시보드 설계

작성일: 2026-08-06  
상태: 사용자 설계 승인 완료, 구현 계획 작성 전 문서 검토 대기

## 1. 목적

현재 Vercel에서 운영 중인 북극 에너지 연구 대시보드를 WebEditor의
`HTML 불러오기` 기능으로 열어 시각적으로 편집할 수 있는 단일 HTML
파일로 제공한다.

편집용 파일은 현재 에디토리얼 화이트 디자인과 연구 내용을 보존하고,
실행 시 ToSuhyeon 저장소의 공개 JSON을 가져와 EIA·OFAC·EU·NSIDC
데이터를 자동 갱신한다. EIA API 키를 포함하거나 공식 API를 브라우저에서
직접 호출하지 않는다.

## 2. 산출물과 범위

새 산출물은 다음 경로에 둔다.

```text
webeditor/arctic-dashboard.html
```

단일 파일 안에 다음 요소를 모두 포함한다.

- 화면의 전체 HTML 마크업
- 반응형 CSS와 인쇄 스타일
- 자동 데이터 로딩·검증·DOM 갱신 JavaScript
- 네트워크 장애 시 사용할 검증된 데이터 스냅샷
- 2025·2027·2033 패권 지수 상호작용
- SVG 기반 시계열 차트와 연구 자료 막대그래프

기존 React/Vinext 화면, `/steel/` 화면, Vercel 배포 설정과 자동 수집
파이프라인은 이번 작업에서 변경하지 않는다. WebEditor에서 저장한 결과를
React 화면으로 자동 역변환하거나 양방향 동기화하는 기능도 범위에서
제외한다.

## 3. 사용자 작업 흐름

1. WebEditor 홈에서 `HTML 슬라이드 편집기`의 `도구 열기`를 선택한다.
2. `HTML 불러오기`에서 `webeditor/arctic-dashboard.html`을 연다.
3. 디자인 화면에서 글꼴, 색상, 여백, 카드 배치와 문구를 편집한다.
4. `미리보기`에서 상호작용과 자동 데이터 갱신 상태를 확인한다.
5. `HTML 저장`으로 수정된 단일 파일을 내려받는다.

WebEditor 편집 캔버스가 스크립트 실행을 제한하더라도 완성된 폴백 DOM을
먼저 표시한다. 자동 갱신은 WebEditor 미리보기 또는 저장된 HTML을 일반
브라우저에서 열었을 때 실행된다.

## 4. 화면 구조

편집용 파일은 운영 화면과 같은 정보 구조를 유지한다.

1. 고정 상단 내비게이션과 연구 섹션 앵커
2. 연구 개요와 주요 출처
3. 자동 데이터 상태 스트립
4. Arctic LNG 패권 지수와 연도 탭
5. `01 · 왜 북극인가`
6. `02 · YAMAL LNG PROJECT`
7. `03 · US ARCTIC STRATEGY`
8. `04 · 4A FRAMEWORK`
9. `05 · KOREA'S POSITION`
10. 출처·자동 데이터 구분·면책 푸터

운영 화면의 화이트·네이비·구리색·블루 색상 체계와 굵은 산세리프 제목,
모노스페이스 보조 서체를 유지한다. 외부 웹폰트가 차단돼도 시스템 글꼴로
자연스럽게 대체되도록 폰트 스택을 정의한다.

## 5. WebEditor 편집 안정성

자동 데이터가 들어가는 요소는 CSS 클래스와 별개로 안정적인
`data-bind` 계약을 사용한다. 예시는 다음과 같다.

```html
<strong data-bind="energy.usLngExports.latest.value">18.10</strong>
<span data-bind="sources.eia.dataThrough">2027</span>
<div data-region="sanctions.watchlist"></div>
```

JavaScript는 태그의 위치나 카드의 시각 클래스가 아니라 `data-bind`와
`data-region`만 찾아 값을 갱신한다. 따라서 사용자가 WebEditor에서 색상,
간격, 테두리, 글꼴과 대부분의 레이아웃을 바꿔도 자동 갱신이 유지된다.

WebEditor에서 자동 데이터 연결 속성을 삭제하거나 이름을 변경하면 해당
항목의 자동 갱신만 중단된다. 이를 줄이기 위해 연결 속성은 화면에 보이지
않게 유지하고, 파일 상단 주석에 보존해야 할 속성을 설명한다.

## 6. 데이터 흐름

브라우저는 다음 공개 파일 하나만 읽는다.

```text
https://raw.githubusercontent.com/suhyeonhong-bit/ToSuhyeon/main/data/processed/arctic_dashboard.json
```

흐름은 다음과 같다.

```text
내장 스냅샷으로 즉시 렌더링
          ↓
공개 JSON 요청 · cache: no-store
          ↓
스키마와 값 검증
     ┌────┴────┐
   성공       실패
     ↓          ↓
최신 DOM 갱신  스냅샷 유지 + 업데이트 지연 표시
```

요청에는 `AbortController` 기반 10초 제한을 둔다. 응답은 화면에 적용하기
전에 다음 핵심 계약을 검증한다.

- `schemaVersion`이 `1`인지 확인
- `generatedAt`이 유효한 UTC 타임스탬프인지 확인
- EIA·OFAC·EU·NSIDC 출처 메타데이터 존재 여부 확인
- 에너지 시계열의 기간·숫자·단위·실적/전망 구분 확인
- 제재 감시 결과의 불리언과 일치 목록 구조 확인
- 해빙 최신 값이 일별 시계열의 마지막 값과 일치하는지 확인

검증 실패 시 일부 값만 적용하지 않고 전체 스냅샷을 유지한다. 서로 다른
시점의 수치가 한 화면에 섞이는 것을 방지하기 위해서다.

## 7. DOM 갱신과 차트

문자열 값은 `textContent`로 넣고, 목록과 표는 `createElement`로 만든다.
원격 JSON을 `innerHTML`로 직접 삽입하지 않는다.

에너지와 해빙 차트는 외부 차트 라이브러리 없이 인라인 SVG로 그린다.
시계열 최솟값·최댓값을 계산해 좌표를 만들고, EIA 실적은 실선, 전망은
점선으로 구분한다. 값이 두 개 미만이면 빈 SVG 대신 `데이터 확인 필요`와
공식 출처 링크를 표시한다.

패권 지수는 자동 데이터가 아닌 연구자 시나리오다. 2025·2027·2033
버튼은 파일에 내장된 연구자 작성 값만 바꾸며 `연구자 추정 · 자동 갱신
아님` 레이블을 항상 유지한다.

## 8. 오류와 상태 표시

초기 DOM은 `내장 스냅샷` 상태로 시작한다. 최신 데이터 확인을 시작하면
`최신 데이터 확인 중`, 성공하면 `실시간 공개 JSON`, 실패하면
`업데이트 지연 · 내장 스냅샷`으로 상태를 바꾼다.

상태는 색상뿐 아니라 텍스트로 제공한다. 사용자 화면에는 네트워크 오류의
기술 세부 정보나 요청 URL 전체를 노출하지 않는다. 개발자 콘솔에도 API
키나 자격증명이 존재하지 않으며, 실패는 짧은 고정 메시지로 기록한다.

## 9. 반응형·접근성

- 데스크톱에서는 2~3열 카드, 모바일에서는 단일 열을 사용한다.
- 상단 내비게이션은 작은 화면에서 가로 스크롤을 허용한다.
- 비교표는 키보드로 초점을 받을 수 있는 가로 스크롤 영역에 둔다.
- 모든 버튼은 실제 `button` 요소와 `aria-pressed` 상태를 사용한다.
- 차트는 `role="img"`와 설명형 `aria-label`을 제공한다.
- 출처 링크의 새 창 이동 여부를 명시한다.
- `prefers-reduced-motion`에서는 전환 애니메이션을 제거한다.
- 포커스 윤곽선을 제거하지 않는다.
- 인쇄 시 내비게이션과 인터랙션 버튼을 숨기고 모든 연구 섹션을 출력한다.

## 10. 보안

- `EIA_API_KEY`, `.env`, GitHub secret을 HTML에 포함하지 않는다.
- 공식 수집 API를 직접 호출하지 않고 검증된 공개 JSON만 읽는다.
- 원격 데이터를 HTML 문자열로 실행하지 않는다.
- 외부 링크는 `https`만 허용하고 새 창 링크에는 `rel="noreferrer"`를 둔다.
- 외부 JavaScript·CSS·차트 CDN을 사용하지 않는다.

## 11. 테스트와 검증

자동 테스트는 다음을 확인한다.

- 산출물이 하나의 HTML 파일로 존재하는지
- 로컬 CSS·JavaScript·이미지 파일 의존성이 없는지
- 공개 JSON URL과 `cache: no-store` 요청이 있는지
- EIA API 키 이름이나 비밀값 전달 코드가 없는지
- 검증된 폴백 스냅샷과 세 가지 데이터 상태가 있는지
- 필수 연구 섹션과 `data-bind`·`data-region` 계약이 있는지
- 패권 지수의 세 연도와 `aria-pressed` 갱신 코드가 있는지
- 모바일·인쇄·reduced-motion CSS가 있는지
- 원격 데이터를 `innerHTML`로 삽입하지 않는지

브라우저 검증에서는 파일을 직접 열고 다음을 확인한다.

- 폴백 DOM이 JavaScript 실행 전에도 읽을 수 있는지
- 최신 공개 JSON 성공 시 상태와 수치·차트가 바뀌는지
- 요청 실패 시 폴백이 유지되고 오류 상태가 표시되는지
- 세 패권 지수 버튼이 키보드와 포인터로 동작하는지
- 데스크톱과 모바일에서 콘텐츠가 겹치거나 잘리지 않는지
- WebEditor의 `HTML 불러오기`에서 문서가 열리고 디자인 요소가 선택되는지

## 12. 완료 기준

다음 조건을 모두 만족하면 구현을 완료한 것으로 본다.

1. `webeditor/arctic-dashboard.html` 하나만 WebEditor에 올려 화면을 편집할
   수 있다.
2. 저장된 HTML을 일반 브라우저에서 열면 공개 JSON 자동 갱신을 시도한다.
3. 네트워크가 없어도 전체 연구 내용과 검증 스냅샷이 표시된다.
4. 현재 대시보드의 주요 섹션, 반응형 구조, 접근성 의미가 보존된다.
5. API 키와 로컬 자산 의존성이 포함되지 않는다.
6. 자동 테스트와 브라우저·WebEditor 수동 검증이 통과한다.
